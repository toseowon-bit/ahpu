# 실제 데이터 연결 전 검증 계획

작성: 2026-10-29. **본 프로젝트에서 인증키를 이용한 실제 API 호출은 수행하지 않았습니다.** 식품안전나라 공식 문서에 회수·판매중지 I0490과 제품명·업체명·품목제조보고번호 등 메타 항목이 존재하는 것은 확인했지만, 실제 응답 필드명·누락률·최신성·완전한 제품 연결은 확인하지 않았습니다. 모든 UI 데이터는 직접 만든 가상 사례입니다.

## 확인할 공식 출처

- I0490: https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=I0490&svc_type_cd=API_TYPE06
- 이용안내: https://www.foodsafetykorea.go.kr/api/howToUseApi.do
- 공지: https://www.foodsafetykorea.go.kr/api/main.do
- 공공데이터포털 회수·판매중지: https://www.data.go.kr/data/15074318/openapi.do

공식 공지 목록에는 2026-09-22부터 OPEN-API 이용 변경 안내가 있습니다. 변경 공지 본문과 신청 계정에 적용되는 조건을 확인해야 하며, 과거 URL 예시만으로 현재 이용 가능 여부를 단정하지 않습니다. 푸드QR·원재료·알레르기 별도 데이터의 제공 범위는 이번 구현에서 검증하지 않았습니다.

## 검증 절차와 통과 기준

| 검증 | 확인 및 남길 증거 | 현재 |
| --- | --- | --- |
| 이용 자격·인증 | 서비스 신청/승인, 최신 공지, 호출량·이용조건 | 미검증 |
| 통신 | HTTPS 지원, 인증키 포함 URL의 서버 로그 마스킹, 타임아웃 | 모의 테스트만 통과 |
| 응답 계약 | 실제 성공/빈 결과/인증 오류, 필드명·타입·서비스별 결과코드 | 미검증 |
| 전체 수집 | total_count와 페이지 누적 수 일치, 중복·변경·삭제·정렬·증분 조건 | 미검증 |
| 식별자 | 품목번호·업체번호 누락/충돌, 수입품·소분·이름 변경 등 표본 검토 | 미검증 |
| 사건 범위 | LOT·제조일·소비기한 원문 보존, 여러 대상 범위 표현 | 미검증 |
| 알레르기 | 해당 품목/버전 표시 출처, 함유/교차접촉 구분, 원문과 대조 | 미검증 |
| 푸드QR | 이용 가능한 데이터/식별자/호출 방식/이용권한을 공식 문서로 확인 | 미검증 |
| 최신성·장애 | 수집시각/원본 등록일 구분, 장애 시 미확인 표시, 복구·중복 억제 | 설계만 |

검증 키가 발급되면 `.env`에 `MFDS_API_KEY`를 설정하고 아래 도구로 최대 5개 원문 행의 **필드명과 개수만** 확인합니다. 도구는 응답을 제품으로 변환하거나 저장하지 않습니다.

```sh
node --env-file=.env scripts/probe-mfds.js
```

`validated:false`는 의도된 값입니다. HTTPS 경로, I0490/RESULT/row/total_count 구조 및 INFO-000 성공코드는 현재 문서 패턴을 기반으로 한 검증용 가정입니다. 빈 결과 등 다른 응답은 오류로 중단하므로 실제 샘플을 확인하여 명시적인 계약과 매핑 테스트를 추가해야 합니다. TLS 실패 시 HTTP로 자동 변경하지 마세요. 키가 없는 환경에서 테스트가 통과해도 실연결 성공을 의미하지 않습니다.

검증된 원문에서 필드별 매핑을 작성하고 별도 live provider를 추가한 뒤에만 운영 모드를 허용합니다. I0490의 회수된 제품 목록을 전체 상품 카탈로그로 간주하지 마세요. 제품명·업체명 검색용 카탈로그와 알레르기 표시 데이터는 별도 확보해야 합니다. 원문 일련번호 기준 사건을 저장하고 제품 연결과 LOT 확인을 독립적으로 검증합니다.
