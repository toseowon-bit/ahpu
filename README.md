# 어푸 · ahpu MVP

제품명·업체명 검색 → 제품 식별정보 확인 → 회수·판매중지 기록 및 알레르기 표시 확인을 위한 초기 프로젝트입니다. **가상 제품 4개와 가상 사건 2개만 사용합니다. 실제 식품의 회수 여부나 안전성을 판정할 수 없습니다.** 실시간 식약처 연결, 전체 상품 카탈로그, 자동 알림은 구현되지 않았습니다.

## 실행

Node.js **24 이상**. 외부 런타임 패키지나 API 키 없이 실행됩니다.

```sh
git clone https://github.com/toseowon-bit/ahpu.git
cd ahpu
npm ci
npm start
```

http://127.0.0.1:3000 접속. 개발 중 자동 재시작은 `npm run dev`, 검증은 `npm run check`입니다. 설정이 필요하면 `.env.example`을 `.env`로 복사하세요. 기본은 로컬 접속만 허용합니다. 외부 환경에서는 HOST, PORT 및 HTTPS 프록시를 별도 설정하세요.

## 구현 상태

| 기능 | 초기 버전 |
| --- | --- |
| 제품명·업체명 검색, 업체 필터 | 예시 데이터에서 동작 |
| 회수·판매중지 목록 | 가상 사건 목록 |
| 제품별 안전정보 | 식별번호 연결 기록과 명칭 매칭 후보를 구분, LOT·기한 표시 |
| 알레르기 표시 확인 | 가상 표시 원문·함유·제조시설 주의 표시·미확인 상태 |
| 관심 제품 등록/해제 | 브라우저 localStorage, 서버 저장·로그인 없음 |
| API 전송 계층 | I0490 검증용 클라이언트, 웹 화면에는 미연결 |
| 자녀 알레르기 비교·푸드QR·일반 바코드·안전정보 알림 | 후속 단계 |

`DATA_PROVIDER=live` 등 demo 외 설정은 시작 단계에서 오류로 중단됩니다. 실제 API 실패를 예시 결과나 ‘회수 없음’으로 바꾸지 않습니다. API 키를 브라우저나 Git에 넣지 마세요.

## 구조

```text
public/                     반응형 화면, 검색·상세·관심 제품
src/server.js               HTTP API 및 정적 파일 허용 목록
src/model.js                도메인 데이터 계약 (JSDoc)
src/matching.js             보수적인 제품 연결 규칙
src/providers/demo.js       명시적인 가상 제품/안전정보
src/providers/index.js      provider 선택 경계
src/providers/mfds-client.js 검증용 I0490 전송 계층
scripts/probe-mfds.js        인증키로 응답 형태 확인 (웹 미연결)
test/                       API·매칭·전송 실패 회귀 테스트
docs/                       아키텍처·API·검증 및 개발 순서
```

검색 예: `우리쌀`은 업체가 다른 제품 2개, `고소한 두유`는 식별번호가 없어 매칭 후보만 표시, `사과`는 알레르기 미확인 상태를 보여줍니다. 관심 제품은 현재 브라우저에서만 유지됩니다. 자동 회수 알림·푸시 권한 요청은 없습니다.

## 다음 개발

실제 데이터 연결 전 [데이터 검증 계획](docs/DATA_VALIDATION.md)을 완료하세요. 데이터 계약과 확장 계획은 [아키텍처](docs/ARCHITECTURE.md), 웹 API는 [API 명세](docs/API.md)에 정리했습니다. 전송 도구와 모의 응답 테스트의 통과는 실제 API 연결 검증을 의미하지 않습니다.
